# PackHub 优化方案

本文档记录 PackHub 在当前 MVP 基础上的后续优化方向。当前版本已经支持局域网部署、用户权限管理、软件 zip 安装包上传和下载，以下内容用于后续迭代规划。

## 当前定位

PackHub 当前适合作为局域网内部的软件安装包管理平台：

- 管理员维护用户和权限
- 管理员上传发行版本、公测版本、历史版本 zip 包
- 用户登录后按权限下载安装包
- 前端 Vue 构建为 `dist`，由 Node/Express 在 `3001` 端口统一托管

当前方案适合用户数量不多、并发下载不高、部署环境偏本地化的场景。

## 优先级建议

建议后续优先按以下顺序推进：

1. 部署稳定性：PM2、Windows 服务、开机自启动、崩溃自动重启
2. 数据存储：从 JSON 升级到 SQLite 或 MySQL
3. 安全配置：默认密码、JWT 密钥、登录保护、上传校验
4. 大文件能力：上传进度、断点续传、下载统计、Nginx 静态下载
5. 权限细化：用户可见软件范围、角色组、操作审计日志

## 一、部署和运行稳定性

当前运行方式：

```bash
npm start
```

这种方式简单，但命令窗口关闭后服务会停止。后续可以优化为：

- 使用 PM2 守护 Node 服务
- 配置 Windows 开机自启动
- 将服务注册为 Windows Service
- 服务崩溃后自动重启
- 将运行日志输出到文件
- 增加启动环境检查，例如 Node 版本、端口占用、数据目录是否可写

推荐先做 PM2 或 Windows Service，因为这是局域网长期使用最直接的稳定性保障。

## 二、数据存储

当前数据文件：

```text
server/data/db.json
```

优点是简单、部署成本低。缺点是并发写入能力弱，数据结构扩展和长期维护不够稳定。

可选升级方向：

- SQLite：本地部署首选，单文件数据库，维护简单
- MySQL：适合多用户和长期运营
- PostgreSQL：更规范，能力强，但部署成本更高

如果 PackHub 主要用于局域网内部，建议优先升级到 SQLite。

可补充能力：

- 数据库迁移脚本
- 定时备份
- 管理员手动备份和恢复
- 数据变更审计

## 三、安装包存储和下载性能

当前 zip 文件保存位置：

```text
server/uploads/
```

当前下载由 Express 的 `res.download(...)` 实现，底层是流式传输，不会一次性把大文件读入内存，普通局域网使用没有问题。

后续可以优化：

- 上传进度条
- 上传失败重试
- 文件大小、类型、hash 校验
- 下载次数统计
- 下载日志记录
- 断点续传
- 大文件由 Nginx 负责下载，Node 只做权限校验
- 无效文件自动清理

如果安装包较大，或多人同时下载，推荐引入 Nginx 承担静态文件传输。

## 四、权限系统

当前权限已经支持基础功能控制：

- 软件下载
- 用户管理
- 软件管理

后续可以细化为：

- 用户只能看到指定软件
- 用户只能下载指定版本
- 用户只能看到指定分类
- 增加角色和权限组
- 支持部门、客户、项目维度授权
- 管理员操作审计日志

这部分适合在真实业务规则明确后再做，避免提前设计过重。

## 五、安全性

当前是 MVP 级别安全能力，后续建议增强：

- 首次登录强制修改默认管理员密码
- `JWT_SECRET` 改为环境变量配置
- 密码复杂度校验
- 登录失败次数限制
- 登录失败临时锁定
- 上传文件二次校验
- 下载链接限时有效
- 操作日志和登录日志
- HTTPS 支持

局域网项目也建议至少完成默认密码修改和 JWT 密钥配置。

## 六、前端体验

当前前端功能可用，后续可以从操作效率和反馈体验继续优化：

- 版本列表搜索、筛选、排序
- 软件分类和标签
- 上传进度显示
- 上传结果反馈
- 下载按钮状态提示
- 版本详情页
- 发布说明和更新日志展示
- 发行版本、公测版本、历史版本分组展示优化
- 后台仪表盘
- 移动端适配

前端优化建议跟业务使用频率结合，高频操作优先优化。

## 七、软件版本管理

当前版本管理已经区分：

- 发行版本
- 公测版本
- 历史版本

后续可以增强为更完整的软件包平台：

- 同一软件下维护多个版本
- 版本号唯一校验
- 当前稳定版置顶
- 公测版标识
- 历史版本归档
- 版本回滚
- 软件分类管理
- 发布说明和更新日志
- 文件 hash 和大小展示

这部分会显著提升平台专业度。

## 八、工程化

后续工程质量可以补充：

- ESLint
- Prettier
- 单元测试
- API 测试
- 环境变量配置
- 构建产物清理
- 自动备份脚本
- GitHub Actions 自动构建
- 发布包打包脚本

工程化优化适合在功能趋于稳定后集中补齐。

## 推荐迭代路线

### 第一阶段：本地稳定运行

- PM2 或 Windows Service
- 开机自启动
- 日志文件
- 防火墙和端口部署说明

### 第二阶段：数据可靠性

- JSON 升级 SQLite
- 数据备份和恢复
- 数据库迁移脚本

### 第三阶段：安全增强

- 修改默认密码流程
- JWT_SECRET 环境变量
- 登录失败保护
- 上传文件校验

### 第四阶段：大文件和体验

- 上传进度
- 下载统计
- Nginx 大文件下载
- 文件 hash 校验

### 第五阶段：业务能力完善

- 软件分类
- 版本详情
- 权限组
- 操作审计日志
